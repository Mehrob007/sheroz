ВВЕДЕНИЕ

Актуальность работы обусловлена необходимостью цифровой трансформации административных процессов в высших учебных заведениях. В современных условиях эффективность управления вузом напрямую зависит от качества и оперативности обработки кадровой информации. Кадровый учёт на уровне факультета имеет выраженную специфику, связанную с иерархической структурой кафедр и разнообразием категорий персонала.

В данной работе представлено решение, ориентированное на максимальную автономность и быстроту развёртывания — веб-приложение, работающее полностью на стороне клиента (Client-Side Only), что позволяет использовать его без сложной настройки серверной инфраструктуры на начальных этапах внедрения.

Целью курсовой работы является проектирование и разработка веб-ориентированной информационной системы для автоматизации процессов учёта сотрудников механико-математического факультета.


ГЛАВА 2. ПРОЕКТИРОВАНИЕ АРХИТЕКТУРЫ СИСТЕМЫ

2.1. Выбор и обоснование стека технологий
Для реализации проекта выбран современный стек технологий, обеспечивающий работу приложения «из коробки» (zero-config):
- Frontend: фреймворк Next.js (React). Обеспечивает компонентный подход и высокую скорость разработки.
- Storage: Web Storage API (LocalStorage). Использование локального хранилища браузера позволяет сохранять данные пользователя между сессиями без необходимости настройки внешней базы данных, что идеально подходит для прототипирования и локального использования в рамках одного рабочего места.
- Styling: Tailwind CSS для создания адаптивного и современного интерфейса.

2.2. Проектирование структуры базы данных
Несмотря на использование LocalStorage, данные структурированы аналогично реляционным или документным БД:
- Employees: массив объектов сотрудников с уникальными ID.
- Departments: справочник кафедр.
- Positions: справочник должностей.
Связи между сущностями реализуются программно на стороне клиента через идентификаторы (PositionID, DepartmentID).


ГЛАВА 3. ПРОГРАММНАЯ РЕАЛИЗАЦИЯ СИСТЕМЫ

3.1. Реализация логики управления данными в LocalStorage
Для работы с данными был разработан абстрактный слой API (lib/api.ts), который инкапсулирует логику работы с LocalStorage. Это позволяет в будущем легко заменить хранилище на полноценную базу данных без изменения кода компонентов.
Основные функции включают:
- getEmployees(): чтение данных из LocalStorage и парсинг JSON.
- createEmployee(data): генерация ID и сохранение обновленного массива.
- seedData(): механизм инициализации хранилища начальными данными факультета (список кафедр мехмата).

3.2. Разработка пользовательского интерфейса на Next.js
Поскольку вся логика вынесена на клиентскую сторону, страницы реализованы как Client Components ('use client'). Это позволяет использовать хуки useEffect и useState для синхронизации интерфейса с состоянием LocalStorage.
Основные компоненты:
- Таблица сотрудников с динамическим поиском.
- Формы добавления и редактирования с выпадающими списками кафедр и должностей.
- Профиль сотрудника с детальной информацией.


ЗАКЛЮЧЕНИЕ

В ходе выполнения курсовой работы была разработана автономная информационная система учёта сотрудников. Использование LocalStorage позволило создать приложение, которое готово к работе сразу после запуска фронтенда, не требуя настройки бэкенда и баз данных.

Основные результаты:
1. Реализована полноценная CRUD-логика на стороне клиента.
2. Создан удобный интерфейс для управления кадровым составом факультета.
3. Разработан механизм инициализации демонстрационных данных.
